# Compare dispatch policies on the same realized world

Method update: October 18, 2026. Proposed experiments below are not reported as executed results.

The simulator already evaluates routes with a common constraint engine. Preserve that advantage when comparing greedy dispatch with Hungarian batches: both policies should receive identical order arrivals, capabilities, shift windows and realized travel shocks for each seed. Different worlds can make a policy difference look larger or smaller than it is. `experiments.runner.run_experiment` with `generate_scenario_bank` already runs every solver configuration on identical scenarios and logs the seed, `scenario_hash` and solver config for each run through `experiments/results/store.save_run`. Travel times are deterministic today (the `sampled` travel-time mode falls back to expected times), so any shock added later must be drawn once per seed and shared.

`python -m experiments.constraint` already separates faster order entry from service capacity: `--front-speedup 2.0` admits work twice as fast while driver shifts stay fixed, and `--policy` picks one of the two scorecard configurations: greedy with `greedy_scorer` and no route optimizer, or Hungarian with the `composite` cost and `nn_2opt`. A gap between them mixes the assignment rule with the cost function and route ordering; to isolate the assignment rule, hold `cost_function` and `route_optimizer` fixed (for example by building both solvers through `SolverRegistry.get_solver`). A useful next step runs both on the same seed and reports queue growth, served orders, and orders that gave up waiting or had no capable driver together. A shorter assignment time can coexist with worse delivery performance. The engine only dispatches routes that meet every deadline, so missed demand shows up as unserved orders rather than late ones; orders that time out or are turned away must remain in the denominator.

The next proposed fixture uses a cold-chain order and a near-end-of-shift driver, then applies a shared pickup delay. Compare completion, infeasibility, waiting minutes and cost per served order across policies. Reject a result that improves mean delivery time merely by serving fewer difficult orders. Seed, scenario hash and solver config are already archived per run; what is missing is a horizon and route-evaluator version tag, so that a route-evaluator change triggers the relevant paired rerun.
